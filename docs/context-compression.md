# Context compression

Echo performs provider-portable context compression in its OpenAI-compatible Chat Completions loops. Each LLM endpoint has **Automatic context compression** and a **Compression threshold (%)** setting. Existing and new endpoints default to enabled at 70%; valid thresholds are 10–95%.

At a safe completed-response boundary, Echo rebuilds the next model request from:

1. fresh system, agent-mode, and editor instructions;
2. the opening user request;
3. a rolling structured summary of retired complete exchanges; and
4. a recent raw tail that retains the latest user work, required media, and complete assistant/tool-call/result groups.

The summary is generated by the active endpoint and model without tools, with thinking disabled so the output budget buys summary text instead of reasoning tokens. Repeated compression folds newly retired exchanges into the prior summary. The cut point between retired history and raw tail may be any assistant or user message — never a tool result — because long agent runs rarely contain user messages after the first one; restricting cuts to user exchanges used to make those sessions incompressible ("not enough completed history"). Large inputs are chunked at those same exchange boundaries against a measured estimate of the real summary request (system prompt + rolling summary + JSON-escaped payload), capped below the endpoint window by the summary output reserve plus a 10% safety margin. Before summarizing, archived tool outputs are pruned to a stub (Hermes-style pre-summarization pruning); units that still overflow are excerpted to bounded head/tail text, and an exchange that cannot fit the summary window even then is dropped from the summary only — the raw transcript always keeps full content for `conversation_history_search` recovery. If a chunk is nevertheless rejected by the endpoint as too large, it is re-chunked at the current limit (splitting or degrading its units), the limit halves once if that cannot shrink the unit, and a unit that still cannot be made smaller is dropped instead of failing the whole compression. Before validation, malformed tool groups in the rebuilt context are repaired (Hermes-style `_sanitize_tool_pairs`): assistant calls whose results were never recorded — for example from a turn interrupted mid-tool-execution — get stub results injected, orphaned tool results are dropped, and id-less calls are stripped. A dangling exchange therefore degrades to a noted gap instead of blocking compression. If a non-streaming summary request times out or fails at the connection level (for example on backends that only serve chat completions as SSE streams), Echo retries that summary call once as a streamed completion before failing the compression; if the endpoint accepts it but returns no content, the same streamed retry runs before the response is treated as empty. If the model stops without producing the summary — for instance by spending its output budget on reasoning — Echo applies the same retry/continue logic used in normal chat turns: it records the empty response and asks the model to continue, up to two times, escalating to a stricter no-preamble prompt on the final attempt before failing the compression. Echo commits a checkpoint only when the summary is nonempty, tool ordering remains valid, and at least 5% or 512 tokens are reclaimed. Normally the rebuilt context must also be at most half the configured trigger; when no boundary can meet that target (for example one oversized exchange in the recent tail), Echo still commits the best available boundary as long as it reclaims meaningfully, so repeated attempts make progress instead of failing identically. A successful compression sets a one-round cooldown before the next automatic attempt; a failed or non-reclaiming attempt backs off for eight rounds so the same failing work is not repeated every other round. Hard-limit preflights (the next request would exceed the context window) ignore the cooldown and always run as the safety valve. If a request is nevertheless rejected by the provider as too large for the model's context window (`exceed_context_size_error` and similar), Echo treats it as recoverable instead of failing the turn: it parses the endpoint's real context size from the error when present, forces an immediate compression against that observed limit, and retries the round. A turn may do this up to three times before failing; the observed limit also corrects the preflight for the rest of the turn when the configured Context Length overestimates the model's real window. When a response stops at its output token limit (`finish_reason: length`), Echo keeps the partial turn and auto-continues from where it stopped, up to two times per turn. Because truncation usually means reasoning tokens consumed the output budget before any answer or tool call was produced, continuation requests run with thinking disabled (the same `enable_thinking: false` mechanism) so the full Max Tokens goes to actual work; thinking returns to the configured mode on the next normally completed response.

The durable transcript remains the canonical raw history. Compression checkpoints do not change visible message indices, media hydration, edit/delete/rerun behavior, or audit history. Editing, deleting, or rewinding invalidates the checkpoint; clearing a chat removes both. After a successful compression, the model receives the deterministic `conversation_history_search` tool for bounded exact-text recovery from retired raw messages, including tool names and arguments.

The main-chat **Compress context now** action runs even when automatic compression is disabled. During an active model/tool loop it queues once for the next safe boundary; while idle it starts immediately. Code Chat and research-agent loops use automatic compression but do not expose this manual action.

Chat activity shows status and token metrics, never the generated summary. The summary is present only in the private checkpoint and the Trajectory inspector. Trajectory records `context/compression_queued`, `context/compression_start`, `context/compression_complete`, `context/compression_skipped`, and `context/compression_error` with trigger, phase, endpoint/model, usage source, token counts, duration, summary-call usage, recovery status, and classified errors.

The design follows the structured-summary and protected-context patterns used by [OpenAI compaction](https://developers.openai.com/api/docs/guides/compaction), [OpenAI Codex](https://github.com/openai/codex/blob/main/codex-rs/core/src/compact.rs), [Claude context editing](https://platform.claude.com/docs/en/build-with-claude/context-editing), and [Hermes](https://github.com/NousResearch/hermes-agent/blob/main/website/docs/developer-guide/context-compression-and-caching.md). It avoids token-deletion compression for agent transcripts so code, paths, errors, identifiers, and tool JSON remain intact.
