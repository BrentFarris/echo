# Context compression

Echo performs provider-portable context compression in its OpenAI-compatible Chat Completions loops. Each LLM endpoint has **Automatic context compression** and a **Compression threshold (%)** setting. Existing and new endpoints default to enabled at 70%; valid thresholds are 10–95%.

At a safe completed-response boundary, Echo rebuilds the next model request from:

1. fresh system, agent-mode, and editor instructions;
2. the opening user request;
3. a rolling structured summary of retired complete exchanges; and
4. a recent raw tail that retains the latest user work, required media, and complete assistant/tool-call/result groups.

The summary is generated by the active endpoint and model without tools. Repeated compression folds newly retired exchanges into the prior summary. Large inputs are chunked at user/exchange boundaries, and a single context-limit rejection is retried with smaller safe chunks. Echo commits a checkpoint only when the summary is nonempty, tool ordering remains valid, the rebuilt context is at most half the configured trigger, and at least 5% or 512 tokens are reclaimed. A one-round cooldown prevents immediate recompression unless the next request would otherwise exceed the endpoint context window.

The durable transcript remains the canonical raw history. Compression checkpoints do not change visible message indices, media hydration, edit/delete/rerun behavior, or audit history. Editing, deleting, or rewinding invalidates the checkpoint; clearing a chat removes both. After a successful compression, the model receives the deterministic `conversation_history_search` tool for bounded exact-text recovery from retired raw messages, including tool names and arguments.

The main-chat **Compress context now** action runs even when automatic compression is disabled. During an active model/tool loop it queues once for the next safe boundary; while idle it starts immediately. Code Chat and research-agent loops use automatic compression but do not expose this manual action.

Chat activity shows status and token metrics, never the generated summary. The summary is present only in the private checkpoint and the Trajectory inspector. Trajectory records `context/compression_queued`, `context/compression_start`, `context/compression_complete`, `context/compression_skipped`, and `context/compression_error` with trigger, phase, endpoint/model, usage source, token counts, duration, summary-call usage, recovery status, and classified errors.

The design follows the structured-summary and protected-context patterns used by [OpenAI compaction](https://developers.openai.com/api/docs/guides/compaction), [OpenAI Codex](https://github.com/openai/codex/blob/main/codex-rs/core/src/compact.rs), [Claude context editing](https://platform.claude.com/docs/en/build-with-claude/context-editing), and [Hermes](https://github.com/NousResearch/hermes-agent/blob/main/website/docs/developer-guide/context-compression-and-caching.md). It avoids token-deletion compression for agent transcripts so code, paths, errors, identifiers, and tool JSON remain intact.
