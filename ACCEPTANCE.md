# Echo acceptance gates

Run `build.ps1 -Release` from the repository root on Windows. It must succeed before distributing a release. The script requires the native toolchains instead of silently skipping missing installations. It builds `echo.exe` and `echo-windows-amd64.zip` on Windows AMD64. The previous application stays in the ignored `OLD/` reference folder and is excluded from release packaging.

For Linux/macOS, run `sh build.sh --release` on the destination OS. Linux requires bubblewrap and usable user namespaces; macOS requires Seatbelt. `.github/workflows/native.yml` defines native Windows/Linux/macOS regression jobs. Cross-compilation is a build check, not runtime acceptance. Do not mark a native platform accepted because its named browser fixture passed on another OS.

## Swarm acceptance

Coordinated update acceptance uses isolated Git repositories and deterministic participant operations to cover pinned commits despite moving upstreams, three-host ordering, lost acceptance responses, partial retries, ownership boundaries, frozen membership, dirty/diverged checkouts, drain cancellation/expiry, replacement revision verification, and reservation retry during maintenance. Deferred schedules retain their identity across restart and execute once. Browser coverage includes peer-only version lag, confirmation, machine-only scope, escaped logs, outage/reload recovery, cancellation and retry. Run `go test ./internal/development ./internal/calendar ./internal/server -run 'TestUpdate|TestRollout|TestDeferred|TestNative|TestLaunch' -count=1` and, from `web`, `npm run test:e2e -- e2e/development.spec.ts e2e/development-rollouts.spec.ts`. Native launcher tests run on Windows and Linux; native macOS replacement acceptance still requires a Mac. Coordinated updater tests do not contact real upstream repositories or restart the user's running Echo.

Windows real-process acceptance is `scripts/test-development.ps1 -Coordinated -Binary <built-echo.exe>`. It creates a private source checkout and local Git upstream, performs a native build/relaunch, publishes a fixture commit, then runs a coordinated machine-only update. It verifies the replacement process's compiled revision, persisted rollout success and final graceful termination. This acceptance passed alongside the full Go tests/vet, 243 frontend tests, 58 browser tests, and Linux updater/calendar/rollout race tests. Windows, Linux AMD64 and Darwin ARM64 builds passed; the Darwin build is not native macOS acceptance.

The Go integration fixtures use separate profiles, secret stores and HTTP servers; transport unit tests exercise actual duplex links. Browser acceptance runs three Echo instances and one deterministic model, with independent remote resources.

## Supported configuration limits

Changed-file summaries cover direct and plugin file operations and bounded native-command snapshots, including partial effects from failed/stopped work. Tests check net-change grouping, safe filenames, persistence/restart, deletion, workspace revocation, rejected cross-chat/unrecorded paths, remote reveal rejection, and keyboard/mobile presentation outside Show work. Native reveal uses Windows Shell item identifiers to select files; deleted paths resolve to an existing allowed containing folder.

Native scoped Shell commands have no network capability and require dependencies/toolchains already available within their grants. Git/Fossil/P4 can receive owner-granted Internet/private-network capabilities without removing filesystem isolation. Native tests verify the actual capability SIDs and denied sibling reads, literal argument preservation and standard input, real scoped Git/Fossil init/add/commit/diff workflows, and a temporary Perforce depot with client forms, add, submit, edit and diff. Perforce networking is tested using the unbound actor because Windows blocks AppContainer loopback by default; its client also runs inside AppContainer for version checks. Settings tests cover permission expansion denial, per-bot toggles, protected ticket storage, output redaction and credential invalidation on destination changes.

Windows native acceptance also runs a Go test with a dependency prepared from a local proxy into the workspace cache, then disables module networking for the sandboxed run. Cache selection tests reject out-of-scope junctions and parent modules. A real frontend DOM test runs under AppContainer using the same Vitest configuration as `npm test`, covering native config loading, dependency resolution and thread workers.

On Windows, existing Git loose-ref repositories and tools requiring denied ancestor metadata can fail explicitly; new scoped Git repositories use reftable. No automatic repository conversion, loopback exemption or unrestricted fallback is performed. Portable toolchain copies are bounded to 512 MiB and reject links. Linux/macOS native tools use their platform sandbox and filtered HTTP(S)/SOCKS egress; tools that ignore proxy settings cannot make direct network connections. Unix SSH/Perforce network compatibility is not covered by the Windows depot acceptance test.

Custom WASI providers and iframe renderers use the documented host contracts. Acceptance includes native compilation and streaming through a provider, endpoint and credential confinement, rejection before dispatch when a recipient disables the provider, hostile custom-renderer output, and per-bot plain-text fallback. Other provider protocols use bounded HTTP responses; compatible endpoints use native SSE streaming.

Echo listens on port 3740 by default and retains the `%LOCALAPPDATA%\Echo2` Windows profile. Unix uses the platform's user configuration directory with the same `Echo2` basename. Exercise the actual configured models and intended projects on each target OS and check their toolchain compatibility. Startup services are opt-in and must be tested separately under the intended user account. Legacy source and local files remain available in `OLD/` for reference.

# Chat notification acceptance

Automated coverage includes independent bot completions, rejection of intermediate/failed/cancelled replies, valid pending questions, durable per-device claims, question resolution and deletion, session isolation/revocation, push encryption and Retry-After responses, and background Swarm journal forwarding without browser sockets. Web tests cover independent preferences/sounds, duplicate tabs and push/live races, notification worker display/click handling, deep links after reload, deleted destinations, and settings at a 390px viewport.

Run `go test ./...`, `npm test`, `npm run build`, and `npm run test:e2e -- notifications.spec.ts pwa.spec.ts` (the npm commands run in `web`). Browser fixtures and the mock model must be rebuilt after Go changes.

Physical-device checks are required before claiming verified Android/iOS background delivery. They have **not** been performed by the implementation's automated desktop tests:

1. Serve Echo through HTTPS and enable notifications separately on desktop Chromium, Android Chrome, and an iPhone/iPad Home Screen installation. Verify permission denial and re-enablement instructions.
2. Start two independent bots in one chat. Leave Echo, lock the phone, and verify each bot's completion notification. Repeat for a pending structured question while another bot continues working.
3. Tap each alert with Echo open, closed, and at the login screen. Verify the correct machine, chat, bot tab, and message; preserve an unsent draft in another chat.
4. Verify distinct original sounds in the running app and platform-controlled sounds while suspended. Test the four independent toggles. Verify one sound/popup per event with two desktop tabs, and no popup while the corresponding bot conversation is focused.
5. Complete a remote Swarm chat with all browser windows closed. Verify phone delivery through the entry server, reconnect recovery, and no duplicate alerts from worker projections. Answer a question before delivery and verify its queued alert is canceled.
6. Revoke the device session and verify no subsequent delivery. Disable push on one device and verify other enabled devices continue receiving alerts. Confirm existing offline-launch and private-cache checks still pass.
